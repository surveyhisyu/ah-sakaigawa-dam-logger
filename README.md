# 境川ダムデータ自動収集（GitHub Actions版）

`nisizatoriver-logger` と同じ考え方で、PCをつけっぱなしにせず
GitHub Actionsが1時間ごとに自動でデータを取得・保存します。

対象サイトはもともとCSVを直接配布しているため、Playwrightなどの
ブラウザ操作は不要で、`requests` + `pandas` だけで完結します。

## ファイル構成

```
（リポジトリ直下）
├── dam_collector.py          データ取得・保存スクリプト
├── weekly_export.py           週次まとめ作成スクリプト
├── requirements.txt          必要ライブラリ
├── .github/
│   └── workflows/
│       ├── dam_scrape.yml    1時間ごとの自動実行設定
│       └── weekly_export.yml 毎週月曜の週次まとめ自動作成設定
└── data/
    ├── dam_data_90013_20260915.csv     日ごとの収集データ（自動生成）
    ├── dam_data_90013_all.csv          全期間まとめたデータ（自動生成）
    └── weekly/
        └── dam_data_90013_20260914-20260920.csv  週次まとめ（自動生成）
```

## セットアップ手順

1. **GitHubで新規リポジトリを作成**
   例: `toyama-dam-logger`（`nisizatoriver-logger`と同じアカウントでOK）

2. **ファイルをアップロード**
   - `dam_collector.py` と `requirements.txt` をリポジトリ直下にアップロード
   - `dam_scrape.yml` は「Create new file」から
     `.github/workflows/dam_scrape.yml` というパスを直接入力して作成し、
     中身を貼り付ける（隠しフォルダは手動でパスごと作る必要があります）

3. **Workflow permissionsを変更**
   `Settings → Actions → General → Workflow permissions` を
   **「Read and write permissions」** に変更（これがないと自動コミットできません）

4. **手動実行して動作確認**
   `Actions` タブ → 「境川ダムデータ自動収集」→ `Run workflow` で
   一度手動実行し、`data/2026-09.csv` のようなファイルが
   自動でコミットされることを確認する

5. あとは放置でOK。毎時08分に自動でデータが追記されます。

## データ形式

- 日ごとにファイルを分割: `data/dam_data_90013_YYYYMMDD.csv`（PCで動かしていた版と同じファイル名規則）
- 全期間をまとめたファイル: `data/dam_data_90013_all.csv`（毎回末尾に追記され続ける）
  ※以前PCで運用していた`_all.xlsx`と同じ役割ですが、GitHubでの自動コミットと
  相性の良いCSV形式にしています（理由は下記「重要」を参照）
- 先頭列に「取得日時」を追加（日本時間 JST）
- ダムコード90013の行のみを抽出して保存
- 列構成: 取得日時, ダムコード, 日付, 時刻, 貯水位, 区分, 全流入量, 全放流量, 貯水率利水容量, 貯水率有効容量
  （「予備」列は境川ダムでは使われていない-99.9固定のダミー値だったため、出力から除外しています）

### 重要: 元サイトのCSVには列名が入っていない

富山県サイトが配布する`dam_data.csv`にはヘッダー行がなく、そのまま読み込むと
1行目のデータを列名と誤認識してしまいます（これが原因で、以前PCで運用していた
際に統合Excelファイルが数百列にまで膨れ上がる不具合がありました）。
`dam_collector.py`では`header=None`で読み込み、固定の列名を明示的に割り当てる
ことでこれを回避しています。

## 取得タイミングについて

サイト側は10分前後の間隔でデータが更新されるため、取得のタイミングが
ずれると「時刻」欄が14:00ではなく14:40のようになってしまうことがあります。
これを防ぐため、次の2段構えにしています。

1. ワークフロー自体は毎時03分に起動する（08分より早め・余裕を持たせる）
2. スクリプト内で、実際に08分になるまで`time.sleep()`で待ってから取得する

これにより、GitHub Actions側の開始タイミングが多少ずれても
（数分程度なら）毎回08分ぴったりで取得できます。

**ただし、GitHub Actionsの遅延が極端に大きい場合（08分を過ぎてから
ワークフローが動き出した場合）は、それ以上待たずにその時点で
即座に取得します。** これは「データが古くなりすぎる」ことを防ぐための
妥協です。この場合は「時刻」欄が08:00きっかりにならないことがありますが、
仕様上の限界としてご了承ください。

## 週次まとめファイルについて

社内の共有サーバー（デスクネッツ等）への保存はセキュリティ上、自動化せず
手動のままにしていますが、「日別ファイルを何個も探して開く」手間を減らすため、
**毎週月曜の朝(JST)に、先週分(月〜日)の日次データを1つのファイルにまとめて
自動生成する**ようにしています。

- 生成場所: `data/weekly/dam_data_90013_YYYYMMDD-YYYYMMDD.csv`
  （例: `dam_data_90013_20260914-20260920.csv` = 9/14(月)〜9/20(日)分）
- 毎週月曜の朝、GitHub上で`data/weekly/`フォルダを見に行けば
  先週分がまとまった1ファイルができています
- そのファイルを開いて「Download raw file」（ダウンロードアイコン）で
  ダウンロードし、手動でデスクネッツ／共有サーバーにアップロードしてください
- `.github/workflows/weekly_export.yml`の`workflow_dispatch`から
  手動実行もできるので、確認したい時はいつでもその場で作成できます

### デスクネッツ等から固定URLでダウンロードする

毎回GitHubのフォルダを開いてファイルを探すのが面倒な場合のために、
**常に同じファイル名で最新週のデータを上書きする`latest.csv`** も
`data/weekly/latest.csv`として自動生成しています。

このファイルは、以下のURLで直接アクセスできます（クリックすると
ブラウザがCSVをダウンロードします）。このURLをデスクネッツの
リンク／ブックマーク機能に登録しておけば、それが「入り口」になります。

```
https://raw.githubusercontent.com/surveyhisyu/ah-sakaigawa-dam-logger/main/data/weekly/latest.csv
```

※このリポジトリはPublic（誰でも閲覧可能）なので、このURLを知っていれば
社外の人でもデータを見られる状態です。境川ダムの公開水位データなので
機密性は高くありませんが、気になる場合はリポジトリをPrivateに変更する
ことも検討してください（Privateにすると、このURLでの直接ダウンロードは
ログイン無しではできなくなります）。

### 日付を選んでダウンロードできるページ

「1週間ぶん」に固定せず、好きな期間を選んでダウンロードしたい場合のために、
`docs/index.html` というページを用意しています。開始日・終了日を選んで
ボタンを押すと、その期間の日次データをまとめて1つのCSVとしてダウンロード
できます（サーバー不要、ブラウザだけで完結する仕組みです）。

**有効にする手順:**
1. リポジトリの `Settings` → 左メニューの `Pages` を開く
2. 「Build and deployment」の `Source` を `Deploy from a branch` にする
3. `Branch` を `main` 、フォルダを `/docs` にして `Save`
4. 数分待つと、`https://surveyhisyu.github.io/ah-sakaigawa-dam-logger/` で
   ページが公開されます

このURLをデスクネッツのリンクに登録すれば、いつでも好きな期間を
選んでダウンロードできる「入り口」になります。「先週(月〜日)」ボタンも
付けているので、毎週の作業はワンクリックで済みます。

## 注意点・前回との違い

- **Excel(.xlsx)への統合保存はしていません。** git管理はテキスト形式のCSVと
  相性が良い一方、xlsxのようなバイナリファイルを毎回追記するとファイルが
  肥大化し、変更履歴も見えなくなるためです。CSVを溜めておけば、あとで
  Excelで開く・pandasで結合するのはいつでもできます。
- サイトが元々CSVを配っているため、時刻はサーバー側のCSVの値をそのまま
  使いつつ、「取得日時」列だけこちら側でJST基準にして付与しています。
  （river.go.jp版のように、ブラウザのタイムゾーン設定で「今」を判定させる
  必要はありません）
- cronは `"8 * * * *"`（毎時8分）としています。ちょうど0分は世界中の
  ワークフローが集中するため公式に非推奨、という点は前回と同じ理由です。

## トラブルシューティング

- **新規アカウント直後は自動実行(schedule)がブロックされることがある**
  → 前回同様、作成から24〜48時間程度で解除されることが多いです。
    それまでは `workflow_dispatch`（手動実行）だけ使えます。
- **エラー: dam_data.csv (404)**
  → ブラウザで `https://kawa.pref.toyama.jp/camera/data/dam_data.csv`
    にアクセスできるか確認してください。サイト構造が変わった可能性があります。
- **ダムコード90013が見つからない**
  → `https://kawa.pref.toyama.jp/camera/02condlist.html?id=0&sel=3` で
    正しいダムコードを確認し、`dam_collector.py` の `TARGET_DAM_CODE` を修正してください。
- **失敗時のメール通知を止めたい**
  → `Settings → Notifications → Email notification preferences` から停止できます。
